## 假设与复算方法

**假设：** 连续重复的部分原因可能是基础模型对“刚出现的同一 Token”存在强烈的条件概率反馈，而不完全是 LoRA 权重变化。

从原始 `results` 按 `forced_token_id`、`phase` 和 `step` 分组，对每组 4 条固定提示词求 Token 119 的**处理后概率算术平均**。先校验原始文件 SHA-256、128 次前向计算、16 条轨迹及每组 4 条提示词；这属于对现有数据的再分析，不是新的推理实验。

在**基础模型**中，人为追加一个 Token 119 后，下一步 Token 119 的平均处理后概率由 2.5941% 增至 26.6776%；若改为追加 Token 8601，则降至 0.8211%。候选模型也出现相同方向的强烈分叉（3.9698% → 25.8984% 或 1.0933%）。

## 可确认结论与限制

1. **新复核发现**：在两种模型中，固定追加 Token 119 都会显著抬高下一步继续选择 119 的概率；固定追加 8601 则使 Token 119 的概率降低。此现象在**未微调的基础模型**上同样存在，支持“重复行为并非 LoRA 独有”的判断。
2. **不能声称根因已经定位**：Teacher Forcing 的历史由实验人为指定；4 条提示词样本极小，且 119 与 8601 是不同 Token，不足以隔离 Token 身份、标点语义、训练数据频率、解码惩罚和模型权重的全部作用。
3. **不能声称 LoRA 改善或退化幅度已精确测得**：例如第 2 步基础模型的处理后概率甚至略高于候选（26.6776% vs 25.8984%）；原始实验 64 组配对的整体差异不能概括每一步的方向。
4. **质量门槛保持拒绝**：Run 12 的 10 条真实生成样例仍为重复标点；本次没有新增 Train Loss、Val Loss、PPL、回答质量评分或 GPU 训练，不晋级、不覆盖已批准版本。
5. **历史对照**：Run 8 与 Run 12 验证集规模不同，不能据较低 Loss/PPL 宣称超越历史最佳。

## 下一次单变量实验建议（尚未执行）

保持基础模型、候选 Adapter、Tokenizer、4 条固定提示词、随机种子和其他参数不变，**仅改变生成解码中的 `no_repeat_ngram_size`（默认无约束 → 3）**，在隔离 CPU 环境比较 10 条固定提示词的重复率、EOS、可读率、Token 分布和安全审核。先进行输入/输出一致性测试，再运行只读推理；不要仅以消除标点重复就判断模型回答正确。只有形成同口径质量提升证据，才考虑可回滚的单变量训练实验。

**经验记录：** 对生成退化，既要做 base-vs-candidate 的同前缀比较，也要做**同模型、不同指定历史**的比较；两者回答不同的问题。报告只记录统计值和哈希，不保存凭据或隐私，不修改保护用户、维护人类的原则。
