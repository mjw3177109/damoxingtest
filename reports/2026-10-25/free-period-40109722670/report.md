## 解释、限制和比较
- **强制历史反馈与自由生成入口不同：** 两种模型在被强制追加句点后都容易继续预测句点；但在本轮自由生成条件下，LoRA 在 2/4 条提示词上直接进入 32 Token 句点循环，基础模型为 0/4。现象支持优先研究 LoRA 候选的**循环入口概率**，不是 LoRA 因果根因的证明。
- **UNK 循环仍存在：** LoRA 在第 4 条提示词上输出 32 个 UNK；不能把单一标点指标改善视为模型修复。
- **与上一轮比较：** 上一轮 Run `40104958975` 是 32 次强制历史下的单步概率审计；本轮是 8 条真实自由生成路径。任务不同，不能将两者的 Top1 次数直接当作同一个质量指标。
- **GPU 历史不变：** 最近真实 Run 12 为 Tesla T4、14.56 GiB、3 epoch、33 步、Train Loss `3.246455`、Val Loss `3.147277`、PPL `23.272599`；本轮新增 GPU 步数为 **0**，没有新的 Loss/PPL。历史 Run 8 验证集不同，不能据此认定 Run 12 超越历史最佳。

## 经验、失败教训与下一步
1. 先区分“模型进入句点循环”与“进入循环后维持重复”。固定历史下的自反馈在基础模型也出现，而自由生成进入循环的频率在本次 LoRA 更高。
2. 必须同时保留 UNK、EOS 和重复率，不能只报告句点 Top1；本轮 LoRA 的 32 个 UNK 是独立的严重质量问题。
3. 下一次只进行一个预注册的 CPU 解码对照：保持模型和数据不变，测试 `no_repeat_ngram_size=2` 是否仅能阻断连续句点，还是能改善**真实可读且相关的回答**；报告负结果，不自动训练或晋级。先做静态/单测/初始化检查，避免无效 GPU 开销。
4. 所有证据去除凭据与原始敏感内容，最小权限，不修改安全保护，不覆盖已批准版本；发现可验证的新阻塞先修复、再验证、后训练。
